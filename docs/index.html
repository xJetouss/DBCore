DBCore – Funktionsreferenz

Die vollständige öffentliche API der Bibliothek: jedes Handle, jede Builder-Methode, jedes Makro, jeden Terminal-Aufruf und jeden Fehlertyp.

DBCore – das Datenbank-Handle

Ein DBCore-Wert ist ein billig klonbares Handle auf ein Datenbankverzeichnis (Clone + Send + Sync). Alle folgenden Methoden sind auf diesem Handle verfügbar.

Konstruktoren

new(name: &str)
Öffnet die Datenbank. Ein reiner Name ("HI") landet unter ./dbcore_data/HI; ein Pfad ("./db", "/abs") wird direkt verwendet.
at(path)
Öffnet das angegebene Verzeichnis.
under(base, name)
Öffnet base/name.
temp()
Wegwerf-Datenbank in einem Temp-Verzeichnis; wird beim letzten Handle gelöscht.

Die Kurzformen melden Fehler auf stderr und liefern ein „geschlossenes“ Handle (is_open() == false). Die try_*-Varianten liefern Result<DBCore, DbError>:

try_new / try_at / try_under / try_temp
wie oben, mit echtem Fehler.

Zustand & Pfad

path() → &Path
Das Verzeichnis der Datenbank.
is_open() → bool
true, wenn die Datenbank geöffnet ist (Schlüssel geladen).

Tabellen verwalten

create(name, schema) → bool
Legt eine Tabelle an. Fehler, wenn sie schon existiert.
create_if_missing(name, schema) → bool
Wie create, aber ohne Fehler bei Existenz.
delete_table(table) → bool
Löscht eine Tabelle (muss existieren).
delete_table_if_exists(table) → bool
Löscht ohne Fehler, wenn sie fehlt.
tables() → Vec<String>
Alle Tabellennamen, alphabetisch.
has_table(table) → bool
Existiert die Tabelle?
try_create / try_create_if_missing / try_delete_table / try_tables / try_has_table
wie oben, mit Result. try_delete_table(table, if_exists: bool).

Zeilen schreiben

add(table, values) → bool
Fügt eine Zeile ein. Doppelte Keys werden abgelehnt.
put(table, values) → String
Upsert. Liefert den (ggf. automatisch vergebenen) Key oder "" bei Fehler.
update(table, key, values) → bool
Partielles Update per Key. true = Zeile gefunden und geändert.
remove(table, key) → bool
Löscht per Key (inkl. ON DELETE CASCADE).
put_many(table, rows) → Vec<String>
Viele Upserts in einem Commit (alles oder nichts).
add_many(table, rows) → bool
Viele Inserts in einem Commit (alles oder nichts).
try_add / try_put / try_update / try_remove / try_put_many / try_add_many
wie oben, mit Result. values ist ein Vec<(&str, String)> – siehe row!.

Zeilen lesen

print(table)
Gibt die Tabelle als Textraster auf stdout aus.
count(table) → usize
Anzahl Zeilen (0 bei Fehler).
all(table) → Vec<Vec<String>>
Alle Zeilen.
get(table, key) → Vec<String>
Zeile per Key. Leerer Vektor = nicht gefunden oder Fehler.
has(table, key) → bool
Gibt es die Zeile?
try_count / try_all / try_get
mit Result; try_get liefert Result<Option<Vec<String>>>.

Abfrage starten

table(name) → Table
Einstieg in den Query-Builder (siehe Table).

Schema ändern (Kurzformen)

Alle laufen als eigene Transaktion. try_*-Varianten liefern Result.

create_index(table, col) → bool
Sekundärer (nicht eindeutiger) Index.
create_unique_index(table, col) → bool
Eindeutiger Index.
drop_index(table, col) → bool
Entfernt einen Index.
indexes(table) → Vec<String>
Indizierte Spalten (inkl. @key und UNIQUE).
add_field(table, col) → bool
Neue Spalte. Bestehende Zeilen brauchen einen Default.
rename_field(table, old, new) → bool
Spalte umbenennen (Foreign Keys werden mitgeführt).
remove_field(table, col) → bool
Spalte entfernen (schlägt fehl, wenn referenziert).
rename_table(old, new) → bool
Tabelle umbenennen.

Version & Migration

user_version() → u32
Schema-Versionsnummer (Start: 0).
set_user_version(v) → bool
Setzt die Versionsnummer.
migrate(steps) → Result<u32>
Führt alle Schritte mit Version > aktueller Version atomar aus. Siehe migrate().

Modelle

create_model::<M>(table) → bool
Legt eine Tabelle aus M::schema() an.
put_model(table, &m) → String
Upsert des Modells (liefert Key).

Wartung

integrity_check() → Vec<String>
Leerer Vektor = OK. Prüft Entschlüsselung/Authentizität aller Blöcke, Typen, NOT NULL, CHECK, UNIQUE/Key-Duplikate und Foreign Keys.

Einstellungen

Werden auf dem DBCore-Handle gesetzt und gelten für alle Klone.

set_busy_timeout(d: Duration)
Maximale Wartezeit auf den Schreib-Lock (Standard 10 s). Wird sie überschritten, kommt DbError::Busy.
set_sync(on: bool)
false = kein fsync – schneller, aber nicht stromausfallsicher.
set_cache(on: bool)
Tabellen-Cache an/aus (Standard an). Aus = minimaler Speicherverbrauch.
clear_cache()
Verwirft alle im Speicher gehaltenen Tabellen.

schema! – Tabellenschema deklarieren

Baut einen Schema-Wert aus Spalten. Jede Spalte hat Name, Typ und optional einen Default. @key markiert den Primärschlüssel. 

schema! {
    @key id: i32,
    name: String,
    views: i64 = 0,
}

Typen für die Spalten:

  • String, &str → Text
  • i8 … i64, isize, u8 … u64, usize → Int
  • f32, f64 → Float
  • bool → Bool
Der Default ist optional. Int-Spalten mit Default vergeben fehlende Keys automatisch fortlaufend.

Schema-Builder

Auf dem von schema! erzeugten Wert lassen sich Constraints und Indizes verfeinern. Alle Methoden geben das Schema zurück (verkettbar).

columns() → &[ColumnDef]
Die definierten Spalten.
not_null(&[&str])
Spalten dürfen nicht leer sein.
unique(&[&str])
Spalten müssen eindeutig sein (erzeugt einen Index).
index(&[&str])
Sekundärer (nicht eindeutiger) Index.
check(col, Check)
CHECK-Bedingung für eine Spalte (mehrfach aufrufbar).
references(col, table, column, OnDelete)
Foreign Key auf table.column (dort muss @key oder UNIQUE liegen).

ColumnDef

Eine einzelne Spaltendefinition. Wird vom Makro erzeugt, kann aber auch direkt gebaut werden – z. B. für add_field.

new(name, kind, default, key)
Konstruktor. default: Option<String>, key: bool.
name() → &str
Spaltenname.
kind() → ColumnKind
Spaltentyp.
default_value() → Option<&str>
Default-Wert.
is_key() → bool
Ist die Spalte der Primärschlüssel?
is_not_null() → bool
NOT-NULL-Flag.
is_unique() → bool
UNIQUE oder Key.
is_indexed() → bool
Hat die Spalte einen Index (auch implizit durch Key/Unique)?
checks() → &[Check]
Alle CHECK-Bedingungen.
foreign_key() → Option<&ForeignKey>
Referenz, falls vorhanden.
not_null() / unique() / indexed()
Builder-Varianten, die die Flags setzen.
with_check(Check)
Fügt einen Check hinzu.
with_reference(table, column, OnDelete)
Setzt einen Foreign Key.

ColumnKind

Der Datentyp einer Spalte.

  • Int – Ganzzahl
  • Float – Kommazahl
  • Text – Zeichenkette
  • Bool – true / false

Constraints im Überblick

Constraints werden beim Schreiben jeder Zeile geprüft. Verstöße liefern eigene Fehler (siehe DbError):

Constraint Wirkung Fehler
Typ Wert muss zum Spaltentyp passen. TypeMismatch
NOT NULL Zelle darf nicht leer sein. NotNull
UNIQUE Wert darf nur einmal vorkommen (leer zählt nicht). Unique
@key Primärschlüssel (implizit UNIQUE + NOT NULL). DuplicateKey
CHECK Bedingung aus Check. CheckFailed
Foreign Key Verweis muss in der Parent-Tabelle existieren. ForeignKey

Check – Bedingungen

Für CHECK-Constraints und Vergleiche. Jede Funktion liefert einen Check.

eq(v) / ne(v)
Gleich / ungleich.
lt(v) / le(v) / gt(v) / ge(v)
<, ≤, >, ≥.
between(lo, hi)
Bereich [lo, hi] (inklusive).
one_of(items)
Aufzählung – Wert muss in der Liste vorkommen.
len(min, max)
Textlänge in Zeichen (nur Text).
like(pattern)
SQL-LIKE: % = beliebig viele Zeichen, _ = genau eins. ASCII-case-insensitive.

OnDelete – Fremdschlüsselverhalten

Restrict
Löschen wird abgelehnt, solange referenzierende Kinder existieren (Standard).
Cascade
Kinder werden mitgelöscht (rekursiv).

Ein ForeignKey-Wert selbst hat die Felder table, column und on_delete und ist über ColumnDef::foreign_key() abrufbar.

row! – Werte einer Zeile angeben

Erzeugt einen Vec<(&str, String)> aus Spaltenname und Wert. Wird von allen Schreibmethoden erwartet. 

row! { id: 1, name: "Alice", views: 5 }

Nicht angegebene Spalten werden mit ihrem Default oder – bei Int-Keys – automatisch befüllt.

Zeilen schreiben

Alle Schreiboperationen laufen – sofern nicht innerhalb einer Tx aufgerufen – automatisch als atomare Transaktion.

Methode Wirkung
add Insert. Fehler, wenn ein @key/UNIQUE-Wert schon existiert.
put Upsert per @key. Fehlt der Key (bei Int), wird er vergeben.
update Partielles Update per Key: nur übergebene Spalten werden geändert.
remove Löscht per Key; löst ggf. Kaskaden und Restriktionen aus.
add_many / put_many Viele Zeilen in einem Commit – alles oder nichts.

Auf jeder gibt es eine try_*-Variante mit Result. Ob ein Key gelöscht wurde, liefert nur try_remove sauber (Ok(true) = entfernt, Ok(false) = nicht vorhanden).

Zeilen lesen

print(table)
Terminal-Raster mit Rahmen.
count(table) / try_count(table)
Anzahl Zeilen.
all(table) / try_all(table)
Alle Zeilen als Vec<Vec<String>>.
get(table, key) / has(table, key)
Zeile per Key bzw. Existenzprüfung.
try_get(table, key) → Result<Option<Vec<String>>>
Unterscheidet „fehlt“ von „Fehler“.

Für alles Weitere (Filter, Sortierung, Joins, Aggregate …) den Query-Builder Table verwenden.

Row – Zugriff auf Zellen

Eine Row ist eine geliehene Sicht auf eine Zeile zusammen mit dem Schema. In Closures (z. B. filter) erhält man sie als Argument.

len() / is_empty()
Anzahl bzw. Fehlen von Zellen.
cells() → &[String]
Alle Rohwerte.
iter() → Iterator<Item=&String>
Iteration über die Zellen.
columns() → Iterator<Item=&str>
Spaltennamen.
str(col) → Option<&str>
Rohwert einer Spalte (None = Spalte unbekannt).
get::<T>(col) → DbResult<T>
Typisierter Zugriff nach Namen.
get_at::<T>(i) → DbResult<T>
Typisierter Zugriff nach Position.
r[i] → String
Zugriff nach Position (fehlend = "").
r["name"] → String
Zugriff nach Namen; unbekannte Spalte = "" + Warnung.

FromCell, FromRow, Model

Traits, die Zellen bzw. Zeilen in Rust-Typen umwandeln.

FromCell

Implementiert für alle Standardtypen (i8 … i64, u8 … usize, f32, f64, bool, String) sowie Option<T> (leere Zelle → None).

FromRow

Wandelt eine Row in einen eigenen Typ. from_row(Row) → DbResult<Self>.

Model

Erweitert FromRow: schema() → Schema und to_values() → Vec<(&'static str, String)>. Wird vom model!-Makro automatisch generiert.

model! – Struct, Schema und Konvertierung in einem

Deklariert ein Struct und implementiert FromRow, Model und schema! dafür. Attribute wie #[derive(...)] werden durchgereicht. 

model! {
    #[derive(Debug, Clone, PartialEq)]
    pub struct User {
        @key id: i32,
        name: String,
        views: i64 = 0,
    }
}

Zusammenspiel mit dem Handle:

create_model::<M>(table)
Legt die Tabelle aus M::schema() an.
put_model(table, &m)
Upsert eines Modells (liefert den Key).
table.collect_as::<T>()
Liest Zeilen als Vec<T>.
table.first_as::<T>()
Erste Zeile als Option<T>.

Table – der Query-Builder

Einstieg über db.table("name"), tx.table("name") oder snapshot.table("name"). Alle Builder-Methoden konsumieren self und geben es zurück – frei verkettbar.

Auswertungsreihenfolge: Quelle/Join → where → group_by/agg → having → order_by → select → distinct → skip → limit.

WHERE-Bedingungen

Alle Bedingungen werden mit UND verknüpft. Die where_*-Varianten können einen Index nutzen – filter nicht.

filter(F)
Beliebige Closure F: Fn(Row) -> bool. Bequem über with!.
where_eq(col, v)
Gleich.
where_ne(col, v)
Ungleich.
where_gt / where_ge
> / ≥.
where_lt / where_le
< / ≤.
where_between(col, lo, hi)
Bereich (inklusive).
where_in(col, iterable)
Wert in Liste.
where_like(col, pattern)
SQL-LIKE (%, _), case-insensitive.
where_in_query(col, subquery)
col IN (SELECT …) – erste Spalte der Unterabfrage liefert die Werte.
where_not_in_query(col, subquery)
wie oben, negiert.

Sortieren & Einschränken

order_by(col)
Sortierschlüssel (ersetzt eine frühere Sortierung). Standard: aufsteigend.
then_by(col)
Weiterer Sortierschlüssel.
asc() / desc()
Richtung des zuletzt gesetzten Schlüssels.
limit(n)
Maximal n Zeilen.
skip(n) / offset(n)
Erste n Treffer überspringen.

Projektion & DISTINCT

select(&[&str])
Nur diese Spalten behalten (in dieser Reihenfolge). Namen dürfen tabelle.spalte sein, wenn nötig.
distinct()
Doppelte Ergebniszeilen entfernen.

Joins

Nach einem Join heißen die Spalten tabelle.spalte. Ohne Präfix sind sie weiter ansprechbar, solange der Name eindeutig ist.

join(table, left, right)
INNER JOIN: left = table.right. left kann auch tabelle.spalte sein.
left_join(table, left, right)
LEFT JOIN: Zeilen ohne Treffer bleiben, rechte Spalten leer.

Joins sind auf einfachen Tabellen erlaubt. Auf Union oder Derived (Unterabfrage) liefert ein Join einen Unsupported-Fehler.

Gruppierung & Aggregate

group_by(&[&str])
Gruppiert nach den angegebenen Spalten.
agg(&[Agg])
Hängt Aggregate an. Ohne group_by entsteht genau eine Ergebniszeile – auch bei leerer Eingabe (Count = 0, Sum = 0, Min/Max = "").
having(F)
Filtert die gruppierten Zeilen (Closure über Row). Nutze with!.

Mengenoperationen & Unterabfragen

union(other)
Vereinigung ohne Duplikate. Beide Seiten brauchen gleich viele Spalten.
union_all(other)
Vereinigung mit Duplikaten.
Table::from_query(q)
Unterabfrage in FROM: weitere Bedingungen, Sortierung, Aggregate etc. auf das Ergebnis von q.

Terminal-Methoden

Führen die Abfrage aus. Jede Kurzform hat eine try_*-Variante mit Result.

Daten

collect() / try_collect()
Alle Treffer als Vec<Vec<String>>.
first() / try_first()
Erste Zeile; leer, wenn keine Treffer. try_first liefert Option.
value() / try_value()
Erste Zelle der ersten Zeile.
values(col) / try_values(col)
Alle Zellen einer Spalte.
exists() / try_exists()
Mindestens ein Treffer?
collect_as::<T>() / try_collect_as::<T>()
Zeilen als Vec<T> (Modelle).
first_as::<T>() / try_first_as::<T>()
Erste Zeile als Option<T>.

Aggregate

count() / try_count()
Anzahl Treffer.
sum(col) / try_sum(col)
Summe numerischer Zellen (nicht-numerische werden ignoriert).
avg(col) / try_avg(col)
Durchschnitt. try_avg liefert Option – None = keine numerischen Werte.
min(col) / try_min(col)
Kleinster Wert (typgerecht).
max(col) / try_max(col)
Größter Wert (typgerecht).

Ausgabe

print()
Terminal-Raster auf stdout.
to_csv() / to_json() / to_html()
Fertige Ausgabe als String (UTF-8). CSV mit BOM und CRLF, JSON als Objektarray, HTML als vollständiges Dokument.
export_csv(path) / export_json(path) / export_html(path)
Schreiben die Ausgabe in eine Datei. Liefern bool.

Streaming & Iteration

stream() → DbResult<RowStream>
Lazy-Iterator mit echtem Fehler pro Zeile. Ohne order_by, group_by, distinct, Joins oder Unterabfragen wird Block für Block von der Platte gelesen (konstanter Speicher).
for row in db.table("t")
Bequeme Iteration (IntoIterator). Fehler werden auf stderr gemeldet und beenden die Iteration.

Mutationen über Abfragen

Filter, Sortierung, skip und limit werden beachtet. Innerhalb einer Tx laufen sie in dieser, sonst in einer eigenen Transaktion.

patch(fields) → usize
Partielles UPDATE. Nur die angegebenen Spalten werden überschrieben. Rückgabe: Anzahl geänderter Zeilen.
merge(fields) → usize
Alias für patch.
delete() → usize
Löscht alle Treffer (inkl. ON DELETE CASCADE).
remove_field(col) → usize
Entfernt eine Spalte aus Schema und allen Zeilen. Der filter wird ignoriert.
try_patch / try_delete / try_remove_field
dieselben Operationen mit Result.

Auf einem Snapshot sind alle Mutationen verboten – sie liefern DbError::ReadOnly.

explain() – Ausführungsplan

Zeigt als Text, wie die Abfrage ausgeführt wird: Scan-Art, genutzte Indizes, Joins, Gruppierung, Filter ohne Index, Limit.

  • SCAN t – vollständiger Scan.
  • SEARCH t USING INDEX col=? – Index wird genutzt.
  • SCAN t USING INDEX col (absteigend, kein Sortieren) – Index liefert Sortierung mit.
  • JOIN / LEFT JOIN tab (Hash-Join …), SUBQUERY, UNION.
  • GROUP BY [… ], HAVING (n Closure(s)), DISTINCT, FILTER (n Closure(s), kein Index), LIMIT n.

Agg – Aggregatfunktion

Bausteine für group_by(…).agg(&[…]). Jedes Aggregat hat eine Ausgabespalte, deren Name sich aus Funktion und Spalte ergibt oder per alias gesetzt wird.

count()
Anzahl Zeilen der Gruppe (Ausgabe: count).
count_of(col)
Anzahl nicht-leerer Werte (Ausgabe: count_col).
sum(col)
Summe (Ausgabe: sum_col).
avg(col)
Durchschnitt (Ausgabe: avg_col).
min(col) / max(col)
Kleinster / größter Wert (Ausgabe: min_col/max_col).
alias(name)
Setzt den Namen der Ausgabespalte.

Tx – Schreib-Transaktion

Eine Transaktion hält exklusiv den Schreib-Lock und arbeitet auf Kopien (Copy-on-Write). Erst commit() schreibt neue Dateien und schaltet sie mit einem atomaren Manifest-Rename scharf. Drop ohne commit() = Rollback.

Erzeugen

db.begin() → DbResult<Tx>
Startet eine Transaktion und wartet auf den Schreib-Lock.
db.transaction(|tx| { … }) → DbResult<R>
Komfortfunktion: Ok → Commit, Err oder Panic → Rollback.

Abschluss

commit(self) → DbResult<()>
Macht alle Änderungen atomar und dauerhaft.
rollback(self)
Verwirft alles. Identisch zum Drop.

Version

user_version() → u32
Aktuelle Schema-Version (inkl. dieser Transaktion).
set_user_version(v) → DbResult<()>
Setzt die Versionsnummer.

Tabellen & Zeilen in der Transaktion

Dieselben Methoden wie auf DBCore, aber als DbResult: create_table, create_table_if_missing, drop_table, rename_table, add_field, remove_field, rename_field, create_index, create_unique_index, drop_index, tables; sowie add, put, update, remove, put_many, add_many, get, has.

Abfragen in der Transaktion

tx.table(name) → Table
Sieht auch die eigenen, noch nicht committeten Änderungen. Damit lassen sich where_*, patch, delete usw. nutzen.
Re-Entrancy: Innerhalb von transaction(|tx| …) immer tx.… verwenden – ein db.… würde auf den eigenen Lock warten und Busy liefern.

Snapshot – fester Lese-Stand

Ein Snapshot friert den aktuellen Zustand der ganzen Datenbank ein. Alle Abfragen darüber sehen exakt denselben Stand – auch über mehrere Tabellen und auch dann, wenn parallel committet wird.

db.snapshot() → DbResult<Snapshot>
Erzeugt einen festen, gepinnten Snapshot. Er bleibt gültig, egal wie viele Schreiber danach committen.
snapshot.table(name) → Table
Abfrage auf dem Snapshot. Mutationen sind verboten (DbError::ReadOnly).
tables() → Vec<String>
Alle Tabellen zum Zeitpunkt des Snapshots.
has_table(name) → bool
Gab es die Tabelle?
user_version() → u32
Schema-Version zum Snapshot-Zeitpunkt.

Indizes

Ein Index liegt im Speicher pro Tabellenstand und wird beim ersten Zugriff gebaut. Die Definition ist persistent. Der Planer nutzt Indizes und den @key automatisch für where_eq, where_in, Bereichsbedingungen und order_by … limit.

create_index(table, col)
Sekundärer (nicht eindeutiger) Index.
create_unique_index(table, col)
Eindeutiger Index. Schlägt fehl, wenn schon Duplikate existieren.
drop_index(table, col)
Entfernt einen Index. Ist die Spalte als UNIQUE referenziert, wird der Drop verweigert.
indexes(table) → Vec<String>
Alle indizierten Spalten (inkl. @key und UNIQUE).

Schema-Änderungen

Alle Änderungen laufen als Transaktion und sind atomar.

add_field(table, ColumnDef)
Neue Spalte. Existieren bereits Zeilen, ist ein Default Pflicht. @key kann nachträglich nicht gesetzt werden.
rename_field(table, old, new)
Spalte umbenennen. Foreign Keys werden mitgeführt.
remove_field(table, col)
Spalte entfernen. Fehler, wenn sie noch referenziert wird oder die letzte Spalte ist.
rename_table(old, new)
Tabelle umbenennen. Foreign Keys werden angepasst.

migrate() – versionierte Migrationen

Führt eine Liste von (Version, Funktion)-Schritten in aufsteigender Versionsreihenfolge aus. Jeder Schritt läuft genau dann, wenn die aktuelle user_version kleiner ist, und setzt die Version im selben atomaren Schritt.

Migration
Typ (u32, fn(&Tx) → DbResult<()>).
db.migrate(&[Migration]) → DbResult<u32>
Führt alle fälligen Schritte aus und gibt die erreichte Version zurück. Mehrfaches Aufrufen ist harmlos (idempotent).

Integritätsprüfung

db.integrity_check() → Vec<String>
Leerer Vektor = alles in Ordnung. Sonst enthält er pro Problem eine Meldung:
  • Entschlüsselung/Authentizität aller Blöcke (Manipulation, Abschneiden, Umsortieren).
  • Typkonformität aller Zellen.
  • NOT NULL, CHECK.
  • Doppelte UNIQUE/@key-Werte.
  • Verwaiste Foreign Keys.

Verwaiste Dateien werden als solches nicht gemeldet, aber beim nächsten Öffnen aufgeräumt.

CSV / JSON / HTML

Alle drei Formate stehen auf Table und – als Kurzformen – auf DBCore bereit. Auf DBCore nehmen die Methoden zusätzlich einen Tabellennamen.

table.to_csv() → String
CSV (UTF-8 mit BOM, CRLF-Zeilen). Zellen werden korrekt escaped (" → "", Felder mit ,/"/Neuzeile in Anführungszeichen).
table.to_json() → String
JSON-Array aus Objekten. Int-/Float-/Bool-Spalten liefern echte JSON-Werte, NaN/inf werden als Strings ausgegeben.
table.to_html() → String
Vollständiges HTML-Dokument mit eingebettetem Stylesheet. Zellen werden escaped.
export_csv / export_json / export_html (path)
Schreiben das jeweilige Format in eine Datei. Liefern bool.

Auf DBCore: to_csv(table), export_csv(table, path) und entsprechend für JSON und HTML.

Web-Interface

open_interface(port: u16)
Startet einen blockierenden HTTP-Server auf 127.0.0.1:<port>. Bietet Übersicht, Tabellenansicht mit Suche, Sortierung, Paginierung, Neu/Edit/Löschen/Upsert-Formulare und Export als CSV/JSON/HTML.

Sicherheit: nur Loopback-Adresse, Prüfung von Host-Header (gegen DNS-Rebinding) und Origin bei POST (gegen CSRF). Zeilen werden über Index plus Fingerabdruck adressiert, damit gleichzeitige Schreiber sich nicht überschreiben.

DbError – Fehlertypen

Alle try_*-Methoden liefern DbResult<T> = Result<T, DbError>. Die Kurzformen ohne try_ melden den Fehler auf stderr und liefern einen neutralen Wert.

Variante Bedeutung
Io Dateisystem-Fehler.
Crypto Authentifizierung/Entschlüsselung fehlgeschlagen (Manipulation, falscher Schlüssel).
Corrupt Beschädigte Struktur.
InvalidName Name enthält unerlaubte Zeichen (erlaubt: a-z A-Z 0-9 _ -).
TableExists Tabelle existiert bereits.
TableNotFound Tabelle fehlt.
RowNotFound Zeile fehlt (z. B. per Key oder Index).
Closed Datenbank ist nicht geöffnet.
SchemaMismatch Spalte unbekannt, mehrdeutig, Pflichtfeld fehlt, mehrere @key …
TypeMismatch Wert passt nicht zum Spaltentyp.
DuplicateKey Doppelter @key-Wert.
BadValue Default enthält unerlaubte Zeichen (:, ,, Zeilenumbruch).
Busy Schreib-Lock-Timeout – anderer Schreiber zu lange aktiv.
NotNull NOT-NULL-Verletzung.
Unique UNIQUE-Verletzung.
CheckFailed CHECK-Verletzung.
ForeignKey Fremdschlüssel-Verletzung (Referenz fehlt oder RESTRICT greift).
ReadOnly Schreiben auf Snapshot oder beendeter Transaktion.
SnapshotExpired Snapshot ist veraltet – neuen holen.
TxState Transaktionszustand ungültig (verschachtelt, beendet, extern verändert).
Unsupported Funktion für diese Abfrageform nicht verfügbar.

DbError implementiert Display, Error und From<io::Error>.

Weitere Makros

with! – Filter-Closure mit Row-Zugriff

Erzeugt eine Closure, in der man eine Row mit Positions-, Namens- und typisiertem Zugriff hat. 

with!(r => r["name"] == "Alice")
with!(r => r.get::<i64>("views").unwrap_or(0) > 0)

Wird als Argument an filter und having gegeben.

remove_if! – Bedingtes Löschen

Kurzform für db.table(t).filter(with!(…)).delete(). Liefert die Anzahl gelöschter Zeilen. 

remove_if!(db, "users", r => r[1].starts_with('A'))
